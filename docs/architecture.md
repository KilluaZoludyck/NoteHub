# Архитектура NoteHub

## Общая схема

NoteHub — клиент-серверное веб-приложение.

Пользователь работает через браузер.
Браузер отправляет HTTP-запросы в Flask.
Flask обрабатывает запрос, проверяет данные и права доступа,
затем обращается к базе данных через SQLAlchemy.

```text
Пользователь
    |
    | Браузер
    v
Frontend (Jinja2 + Bootstrap)
    |
    | HTTP-запросы
    v
Backend (Flask)
    |
    | SQLAlchemy
    v
SQLite
```

## Принципы архитектуры

1. Frontend не обращается к базе данных напрямую.
2. Backend проверяет все данные и права доступа.
3. Пароли хранятся только в хешированном виде.
4. Личные заметки доступны только автору и администратору.
5. Публичные заметки доступны всем авторизованным пользователям.
6. Администратор может работать с любыми заметками.
7. Каждая функциональная область выделена в отдельный blueprint.
8. Секретные данные хранятся в переменных окружения.

## Модули приложения

| Модуль | Blueprint | Ответственность |
|---|---|---|
| Главная | main | Главная страница, информация о проекте |
| Авторизация | auth | Регистрация, вход, выход |
| Заметки | notes | CRUD заметок, поиск, публичные заметки |
| Профиль | profile | Просмотр и редактирование профиля |
| Администрирование | admin | Управление пользователями и заметками |

## Поток данных

1. Пользователь открывает страницу.
2. Браузер отправляет GET-запрос.
3. Flask находит нужный маршрут.
4. Flask проверяет, авторизован ли пользователь.
5. Flask обращается к базе данных.
6. SQLAlchemy возвращает данные.
7. Jinja2 формирует HTML-страницу.
8. Браузер отображает страницу.

При создании заметки:

1. Пользователь заполняет форму.
2. Браузер отправляет POST-запрос.
3. Flask-WTF проверяет CSRF-токен и данные формы.
4. Backend проверяет обязательные поля.
5. Backend определяет автора как текущего пользователя.
6. SQLAlchemy сохраняет заметку.
7. Пользователь видит сообщение об успехе.
